# OPC Creative Acceptance Pass

Use this pass when the creative-production normalization work is near closeout and you want one practical read-through instead of another rule-adding burst.

## Acceptance question

If a new creative-production failure landed tomorrow, would the repair naturally route to:
1. the main creative operating protocol
2. the correct owner file
3. the verification gate when delivery claims matter
4. a remaining-items-only control surface if more normalization work appears

If the answer is yes, the normalization work is near practical acceptance.

## Quick pass checklist

- [ ] A broad production failure would route to `references/opc-creative-operating-protocol.md`
- [ ] A story-to-video production request would route to `skills/story-to-video-director/SKILL.md`
- [ ] A question about whether a claimed result is real would route to `references/opc-creative-verification-gate.md`
- [ ] A question about dead background monitoring would route to `references/opc-background-monitoring-guardrails.md`
- [ ] A question about broken delivery/auth state would route to `references/opc-delivery-auth-failure-handling.md`
- [ ] A question about over-optimistic closeout wording would route to `references/opc-creative-closeout-language-rules.md`
- [ ] A question about default continuation after sub-results would route to `references/opc-creative-auto-handoff-map.md`
- [ ] A question about ownership confusion between files would route to `references/opc-creative-ssot-map.md`
- [ ] Remaining work, if any, would go to `references/opc-creative-normalization-todo.md` rather than a new ad-hoc note

## Pass condition

Pass when the routing path feels obvious and there is no strong temptation to create another parallel creative-policy file.

## Fail condition

Fail when a new issue would likely cause:
- another duplicated rules file
- another broad summary instead of an owner-file update
- another optimistic delivery claim without verification
- another progress report that functions as a fake control surface
