# OPC Creative Chief-Controller Checklist

Use this checklist during creative-production runs.
The point is to keep the main session acting like a chief controller instead of drifting back into narrator mode.

## Core rule

If the main session mostly explains, waits, or relays worker claims, it is not controlling the run yet.

## Quick self-check

Before replying mid-run, ask:
1. Did I assign enough real lanes, or only planning lanes?
2. Did the latest result trigger a next action, or did I just explain it?
3. Do I know the current artifact level honestly?
4. Has project truth been synced after the latest material change?
5. Is the active delivery path verified and still valid?
6. If a background monitor exists, is it watching a live path?
7. Am I about to say “almost done” without L4/L5 evidence?
8. Can I push one more meaningful step internally before talking to the user?

## Default action bias

If the answer to question 8 is yes, prefer doing that next internal step before replying.

This checklist should be read as the chief-controller slice of the broader creative operating protocol, not as a standalone motivational note.
For SSOT ownership, see `references/opc-creative-ssot-map.md`.

## Escalation conditions

It is appropriate to interrupt the user when:
- a real artifact is ready
- a blocker cannot reasonably be solved internally
- a path has hard-failed and needs user choice
- the user explicitly asked for status

## Anti-patterns

Do not normalize these:
- “I’ve started X, Y, Z” as a substitute for production evidence
- “still monitoring” as a substitute for liveness
- “almost there” without verified preview or delivery
- asking whether to continue when the next low-risk step is obvious
