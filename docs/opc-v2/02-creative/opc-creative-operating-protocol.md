# OPC Creative Operating Protocol

This file unifies the main operating contract for creative-production OPC runs.
It exists to connect the manager layer, director layer, board/status layer, verification gate, handoff map, and closeout language into one protocol.

## Core rule

A healthy creative-production run should behave like one coherent production system.
It should not feel like disconnected advice, worker optimism, background watching, and late delivery improvisation.

## Protocol phases

### 1. Route correctly
- if the task is broad production work, keep manager/director posture
- do not prematurely collapse into one execution lane
- choose the production director path when the user wants a result object spanning several layers

### 2. Open enough lanes
- launch enough real production lanes early
- define ownership for script/shot, visual, audio, render, and delivery where relevant
- distinguish parallelizable work from serial bridge work

### 3. Attach state truth
- maintain a board or status view that separates claimed from verified state
- keep project truth synced as assets, drafts, and delivery state change
- background monitors must track real liveness rather than ceremonial waiting

### 4. Auto-handoff by default
- treat each meaningful result as a trigger for the next action
- do not wait for user prodding after every sub-result
- if there is no obvious next action, make that explicit in planning or status

### 5. Verify before promotion
- do not promote worker claims directly into user-facing success
- do not promote planned fallback into executed fallback
- do not promote monitored jobs into proof of progress
- do not promote draft/preview into delivery unless the user explicitly wanted that level

### 6. Speak at the verified layer
- user-facing language must match the highest honestly verified layer
- if the state is mixed, separate verified progress from missing pieces and blockers
- summaries should reduce ambiguity, not cosmetically improve morale

### 7. Close out honestly
- only call the run complete when the requested result is directly accessible, unless an earlier level was explicitly requested
- if the run is incomplete, keep completed / missing / blocker / next step distinct
- preserve durable behavioral corrections to the smallest correct layer

## Unified anti-pattern set

This protocol exists to prevent these from reappearing in different clothes:
- planning-heavy starts with downstream lanes missing
- commentary loops after sub-results
- worker-claim inflation
- mocked or zero-byte artifacts entering success paths
- background monitors mistaken for production motion
- broken delivery/auth paths still treated as alive
- summary language outrunning verified state

## Success condition

A strong creative-production run should show all of these together:
- enough early lane activation
- real artifact-level movement
- automatic continuation
- explicit verified vs claimed state
- delivery viability known before late-stage panic
- user-facing language that stays honest
