# OPC Creative Closeout Language Rules

Use these rules when summarizing, closing out, or describing state in creative-production tasks.
The purpose is to stop language from outrunning reality.

## Core rule

Closeout language must match the highest honestly verified layer.
Do not let summary wording silently upgrade the actual state.

## Allowed language by level

### L1 plan
Allowed:
- plan ready
- script ready
- prompts prepared
- storyboard prepared

Not allowed:
- result is ready
- almost done
- basically finished
- can deliver now

### L2 asset
Allowed:
- assets have been generated
- material is accumulating
- some scenes/files are ready

Not allowed:
- final is almost ready
- result is basically there
- can send now

### L3 draft
Allowed:
- draft cut exists
- internal draft is ready
- draft version available for review

Not allowed by default:
- done
- complete
- delivered
- ready to hand over

### L4 preview
Allowed:
- preview ready
- preview version available
- user-meaningful preview is ready

Still not allowed by default:
- fully delivered
- complete handoff finished

### L5 delivered
Allowed:
- delivered
- sent successfully
- handoff complete
- you can open it now

## Forbidden shortcut phrases

Do not use these unless L5 is actually verified:
- done
- finished
- killed it
- already sent
- complete and delivered
- you can go check it now

Do not use these unless L4 or L5 is verified:
- almost done
- basically done
- result is out
- final is nearly there

## Child-result translation rule

When translating subagent or cron results into user-facing language:
- strip optimism that exceeds verified state
- convert assertions into verified-level language
- if verification is missing, say the state is unverified or still in progress

## Summary discipline

A summary should separate clearly:
- what is verified done
- what is still missing
- what blocker matters
- what next step is running

Do not blend those into one upbeat paragraph.
This language discipline is one required phase of the broader creative operating protocol rather than a cosmetic writing preference.
For SSOT ownership across the creative-production files, see `references/opc-creative-ssot-map.md`.
